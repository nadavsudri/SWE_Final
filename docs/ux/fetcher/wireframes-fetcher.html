Wireframes: the structure is up for debate; styling doesn't exist yet. Values come from the cached fixture (ISR, 34.5,30.5,35.45,31.6) unless a note says otherwise.

First visit: nothing set, empty cache

1 Inputs left, map centre, fetch right: the order of the work. The Fetch panel is always there, so the reason the button is disabled is always visible.

2 Profile and Sources say what they will contain instead of rendering empty forms.

3 The map hint names the keyboard path as well as the mouse one (include).

4 Saved areas (0): the tab is still shown so returning users learn where saved areas live.

Area set, ready to fetch (cached fixture)

1 Readout = exactly what the backend will use: bbox, km², area_id (the cache folder name).

2 The profile card says which profile applies and why; without a key the LLM button is disabled with its reason next to it, not in a tooltip.

3 Each source row predicts reuse vs download from /api/snapshots (same params and younger than TTL). The UI never re-implements TTL rules.

4 The plan line turns the five predictions into one sentence before anything runs. Real fixture: districts and facilities reuse; population rebuilds from the shared download.

Sources: options open, with validation errors and the pin

1 Options sit under their own row (progressive disclosure); Area and Profile collapse to a one-line summary to make room.

2 Validation is inline, names the rule, and uses the field's own terms (“ADM2 is a geoBoundaries level”). Errors read from glyph + text, not red alone.

3 Edited profile options say so and offer Reset to profile: the user sees that their edit overrides the profile (fetch_all merges it that way).

4 Pin lives in the row's options, listing that source's snapshots with their age. Facility tags are removable chips plus a key/value adder.

Area: GeoJSON upload rejected

1 The rejected file is named, the reason uses the server's words (Area.from_geojson rules), and the fix is one sentence.

2 The previous area (if any) is kept; a bad file never wipes a good shape.

3 Other messages in the same slot: “Not valid JSON”, “Not GeoJSON (no type)”, “Geometry is invalid (edges cross)”, “Coordinates out of range: expected lon/lat”.

Area: outside the country (warning) and too large (block)

1 Blocks and warnings look different: a block has the error border and disables Fetch with the reason; a warning is neutral and leaves Fetch on.

2 Outside-the-country is a warning, as specified: it states the share outside and offers to show the ADM0 border on the map.

3 Limits (20,000 warn / 100,000 block km²) come from /api/config. The 20,000 warning uses the same neutral callout.

4 Numbers in this frame are illustrative (no such area is cached).

Returning user: saved areas

1 Two cached areas share the name “negev”: the area_id and size tell them apart, and hovering a row outlines its shape on the map.

2 Rows say how complete each area is (sources present) and how old its newest snapshot is: the facts that decide whether to re-fetch.

3 After opening the older one, its rows predict: population, roads, transit reuse; districts and facilities download because those fetchers' params changed since (real cache state).

Fetching: slow source, cache hits resolve instantly

1 One row per source (one fetch_all call each): cache hits show “reused” immediately, so the user sees progress from the first second.

2 Elapsed time per running source, plus a line that sets expectations after 10 s.

3 No cancel, said plainly with what the user can do instead (leave; the job lives on the server).

4 Inputs lock during the job so the plan can't drift from what is running; the map stays usable.

Partial failure with Retry (network off: the real offline outcome)

1 Failure is per source: the word “failed” + glyph + the error message, never colour alone. Successful sources stay usable.

2 Retry re-runs that source only, with the same area, options, profile and pin; a second failure says “failed again (2 tries)”.

3 These two failures are what the cached fixture really does offline: Overpass and the GTFS catalog need the network.

4 The Fetch button stays enabled after the job: running it again follows the plan line.

Results: cards, district + facility layers

1 One card per source: summary in words first, then snapshot id, fetched_at, folder and files with sizes. Real fixture values.

2 Layers: area = dashed line, districts = solid outline + name label, facilities = diamonds that cluster into numbered circles when zoomed out. Shape and line style identify each layer without colour (include).

3 Facility popup shows the name and the tags the fetcher saved (amenity, healthcare, emergency, osm_id).

4 The popup shows a real record from the cached facilities.geojson. View manifest: next frame.

Manifest viewer (read-only drawer)

1 Raw manifest.json, read-only, with Copy and the file path. Esc closes; focus returns to the View manifest button that opened it.

2 The drawer covers the map, not the result cards, so the user can open another card's manifest without closing first.

3 Long values wrap; the hash and URLs stay selectable for copying.
